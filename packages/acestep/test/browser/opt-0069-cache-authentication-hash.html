OPT-0069 — complete warm-cache SHA-256 A/B screen

This explicit-button, CPU-only benchmark authenticates the pinned main, revision-7 dense-DiT, and revision-6 VAE manifests, derives their real production acquisition subsets, and refuses to run unless all 158 logical records resolve to the exact 156 marker-qualified OPFS payloads totaling 7,325,999,133 physical bytes. It never requests a GPU device and never writes, removes, or republishes a cache entry.

The fixed balanced order is A1, B1, B2, A2, B3, A3, A4, B4. A is the current sequential File.stream() plus AceIncrementalSha256 path with at-most-4 MiB slices. B is sequential whole-file File.arrayBuffer() plus WebCrypto SHA-256, with exactly one sub-128 MiB payload live and a conservative transient bound below 384 MiB. Every arm gets a fresh worker, independently repeats exact digest verification, and reports both the complete path and the retained 102-file / 5,731,837,696-byte (5.7318 GB) upload slice. The optional WASM arm is deliberately absent until a true dependency-free four-file SIMD owner and its matched scalar reader control are independently proven.

Before opening this page, run pnpm exec vite --host 127.0.0.1. The URL must include complete coreCommit, harnessCommit, machineModel, osVersion, osBuild, browserVersion, cpuCoreCount, and memoryBytes query parameters. Do not start while another benchmark, build, or heavy process is active.
