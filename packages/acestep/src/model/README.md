# Browser model boundary

This directory is the Stage 1 browser-side consumer of the package generated by
`model/convert.py`. It does not define a second model format.

- `manifest.ts` fail-closes the canonical `ace-step-webgpu-v1` schema, profile,
  pinned snapshots and provenance, payload/license inventory, accounting,
  tensor layouts, spans, dtype policy, and logical row-part coverage. It also
  resolves a complete logical tensor or requested row interval into ordered
  runtime-axis-0 pieces, including embeddings split across package shards.
- `package.ts` hashes the externally pinned manifest bytes before UTF-8 decode
  or strict JSON parsing. It also streams package payloads through bounded,
  transactional writes and publishes them only after exact length and SHA-256
  verification. Its resumable path authenticates every retained prefix,
  validates exact `Range`/`Content-Range` suffixes, safely restarts when a
  server returns a complete 200 response, and applies a bounded retry policy.
- `cache.ts` supplies the content-addressed OPFS primitive. Verified entries
  require a separate marker and remain untrusted until acquisition re-hashes
  their bytes. Interrupted entries remain invisible partials; a resumed writer
  must hash its exact prefix before appending, or explicitly restart from zero.
- `acquire.ts` inventories the selected package, authenticates every cached
  runtime file (including tokenizer/config assets), deduplicates physical
  content identities, inspects quota when available, and drives sequential
  bounded resumable downloads. Persistence is an explicit user-action helper,
  never a side effect of inspection.
- `sha256.ts` is the bounded incremental hash implementation adapted from the
  MIT-licensed Parakeet implementation at pinned commit
  `7ee112738262a6f5a0efd2f150748a4087432fbb`.
- `gpu-upload.ts` re-hashes an OPFS/file body while copying only bounded,
  four-byte-aligned chunks to a scoped WebGPU allocation. Validation/OOM,
  cancellation, short-body, and digest failures destroy the tentative buffer;
  graph assembly sees only a fully authenticated result.
- `gpu-tensors.ts` loads an explicit phase-lifetime set transactionally,
  publishes logical tensors only after every required shard is authenticated
  and resident, preserves row-sharded bindings, and destroys the entire phase
  on failure or after the graph owner drains the queue.

The real pipeline backend still needs to allocate each graph's activation
arena, bind the phase tensors to the model composers, connect progress and
recovery to the worker/UI, and enforce drain-before-destroy across phases. The
acquisition and phase-residency foundations are complete, but they are not
inference by themselves.
